# 构图、网格与节奏

> 何时读：设计文稿里写逐页构图、节奏和签名画面时；成稿时某一页构图拿不准时。

## 1. 网格

画布为 16:9，13.333 × 7.5 英寸。默认网格：

- 左右边距 0.75–0.9 英寸，上边距 0.65–0.8，下边距 0.55–0.65。
- 12 栏，栏间距 0.2–0.25 英寸。代码里用 `k.col(n)` 取第 n 栏的 x，用 `k.span(a, b)` 取 a 到 b 栏的 `{x, w}`。
- 所有文字和主要对象的左边缘落在栏线上。打破网格（出血图片、越界的大字）必须是有意的，并在代码里标注 `bleed: true`。
- 垂直方向不强制基线网格，但同类元素在不同页面上的 y 坐标保持一致（例：所有普通页的标题都在 `k.M.top`）。

## 2. 构图动作（不是模板）

先确定这一页的**主角**和**页面任务**，再从下面选一个构图动作，然后按内容调整比例。同一个动作在不同页面上应该长得不一样。

| 构图动作 | 适合 | 要点 |
|---|---|---|
| **论断**（Statement） | 核心观点、转折、结论 | 一句话，36–66pt，左对齐，放在画面上部约 1/3 处；其余全部留白；强调色只落在两三个关键字上 |
| **主体 + 旁注**（Hero + annotation） | 解释一个对象：结构、模型、图片 | 主体占 55–70% 的面积；标注用细引线贴近被标注的部位，而不是排在旁边的列表里 |
| **满版图像**（Full-bleed） | 情绪、场景、真实证据 | 图片铺满或出血；文字放在图像安静的区域；必要时加局部的纯色遮罩，不用渐变蒙版 |
| **并置对照**（Juxtaposition） | A 与 B 的差异 | 两个对象用同样的尺度、共用同一条基线；差异处用强调色；比例可以不对称 |
| **序列**（Sequence） | 过程、算法步骤、演变 | 横向或纵向排成一条；状态之间的变化是重点；适合拆成多页 Morph |
| **数据焦点**（Data） | 一个数量关系 | 标题直接说出结论；一个图表；直接标注，不用图例；强调色只给重点系列 |
| **大数字**（Number） | 一个关键量 | 96–200pt 细字重数字 + 一句说明；不加框 |
| **剖面 / 展开**（Anatomy） | 复杂系统的组成 | 中心是整体，外围是部件，用细线连接；或者跨页 Morph 从整体放大到局部 |
| **引文**（Quote） | 权威观点、原始文献 | 衬线体大字号，出处用 caption；不用巨大的引号装饰 |
| **章节**（Section） | 结构转换 | 编号 + 章节名，加上这一章的意象图；与整套同一个世界，靠尺度和光的强弱区分，不换底色 |

## 3. 视觉中心与视线路径

每一页先定视觉中心，再安排其余元素：

- **只有一个中心**：最亮、最大、对比最强的东西只能有一个。其他元素降一档：更暗、更细、更小。
- **引导视线**：用引导线、连线的走向、元素的排列方向、光的位置，把视线从页面入口（通常是左上的标题）带到中心。连线可以从弱到强排列，最强的那条落在中心上。
- **光落在中心上**：在暗场风格里，视觉中心就是光源，背景的光照衰减也以它为中心（`texture.js --light`）。
- **动效也指向中心**：逐步出现的顺序通常是“先铺背景，再点亮中心”。
- 检查方法：把渲染图缩小到拇指大小，或者眯眼看，第一眼落在哪里？如果不是中心，就调整。

## 4. 尺度与比例

- **拉开反差**。主角要大到不需要寻找：一个缩在角落里的小图解，等于没有主角。主次之间的比例常见 2:1、3:2、5:3；内容本身对等时才用 1:1。
- **留白集中**。把空白集中成一块大的，而不是均匀撒在各处的小缝隙。
- **敢于出界**。巨大的字、出血的图、超出画面的结构，能让页面有张力。出界要有意为之（代码里标 `bleed: true`）。

## 5. 节奏：整套的强度曲线

把整套演示当成一部片子来排。先画出叙事的起伏，再让画面的强度跟着它走：

| 叙事段落 | 常见的画面强度 |
|---|---|
| 开场：抛出问题或悬念 | 强：一个让人停下来的画面 |
| 铺垫：建立基础概念 | 中：清楚的图解，节奏平稳 |
| 推进：机制、证据、细节 | 中到高：信息页，可以很满 |
| 转折或揭示 | 最强：签名画面、最亮的光、满版图、巨大的数字 |
| 收束：结论和回响 | 由强转静：一句话，或回到开场的画面 |

每页标一个节奏标签，用来描述它的强度和任务（QA 会用 `dense` 判断这一页是否需要图）：

| 标签 | 含义 |
|---|---|
| `anchor` | 结构性页面：封面、章节、结尾 |
| `breathing` | 安静页：论断、引文、大数字、满版图 |
| `dense` | 信息页：图解、数据、对照、公式 |

强度靠光的强弱、尺度、画面的满与空来变化，**不靠换底色**：整套保持同一个世界（`principles.md` 第 2 条）。

检查时看缩略总览，问这几个问题，而不是数页数：

- 强度是不是一条平线？观众会不会在某一段失去注意力？
- 高潮落在叙事的转折处了吗？还是落在了无关紧要的地方？
- 连续几页的构图、密度是不是太相似？Morph 序列除外，那是有意的连续。
- 有没有哪一页跳出了这个世界（底色、质感、图形语言不一致）？
- 封面、目录、章节页是按需设置的，还是机械添加的？短演示通常不需要目录页。

## 6. 签名画面

每套演示指定 1–3 页**签名画面**：观众离开会场后还记得的画面。通常是封面、叙事的转折点，以及最重要的那张图。

- 在设计文稿中指定，并写清它为什么值得被记住。
- 签名画面不受“克制”的约束：可以用整套最大的尺度、最强的颜色、最复杂的图、最长的 Morph 序列。
- 制作时给它们不成比例的时间：做不止一个版本，并排比较，多打磨几轮。
- 签名画面之外的页面要为它们让路：在签名画面之前适当压低强度，高潮才会显得高。

## 7. 结构层

大面积的平涂底色避开了 AI 味，放映时却可能显得单调。解决办法不是铺图片背景（会和图解抢场地），而是加一层**结构层**：杂志和工程图里那些承载信息的细小元素。

判断标准：每个结构元素要么**承载信息**（导航、关系、度量），要么是**整套固定的系统**（每页同一位置、同一样式）。一次性的点缀不算结构层，见 `anti-ai.md` 的“通用部件”。

| 元素 | 承载的信息 | 用法 |
|---|---|---|
| **导航框架** | 讲到哪了 | 右上角为章节编号和章节名（label 字号），左下角为进度标记（用母题绘制：已讲深、当前强调色、未讲浅），右下角为页码。用于普通内容页；封面、章节页和结尾页不用 |
| **引导线 / 旗标标注** | 这句话说的是图上哪一处 | 0.5pt 细线加末端小圆点。**走向要和图本身的线条明显不同**（图是斜线，引导线就用竖线），否则会被误读成图的一部分 |
| **尺寸线** | 多长、多大、哪一段 | 工程图式：细线加两端短竖线，标注在下方 |
| **刻度与对位** | 这一步对应图的哪一列 | 例：把公式拆成几步，分别对齐到画它的那一列，在分隔线上用刻度相连 |
| **色块分区** | 这一块是不同的区域（输入 / 输出、正文 / 注释） | 整块平涂次背景色（paperDeep），可以出血；不加圆角、阴影和边框。分区内的小字改用 graphite 色，以保证对比度 |
| **纸张颗粒 / 光照** | 质感（整套统一）；深色页上由主体驱动的光 | `node engine/texture.js <背景色> assets/grain-paper.jpg` 生成，在 theme 中设置 `backgroundImages: { paper: ... }`。浅底强度约 1，深底约 0.5；深色页可加 `--light`（见 `color.md`）。必须在投影或大屏上确认效果 |

- 结构层在**设计阶段**决定：这套演示用哪几种，写进 `design.md` 的“结构层”一节，并实现在 deck 的 `parts.js` 里（模板见 `templates/deck/parts.js`，实例见 `examples/attention/parts.js`）。
- 结构元素必须比内容更轻：字号用 label 或 caption，颜色用 stone 或 graphite，线宽 0.5pt。如果它比图解还抢眼，就是做错了。
- 不加 Logo，除非用户要求。

## 8. 章节页

章节页是节奏上的“换气”，也是签名画面最常出现的地方。

- **系统一致**：与整套同一个世界（同样的底色、质感和图形语言）；编号的字体、字号和位置，章节名的样式，整套保持一致。
- **主视觉各不相同**：每个章节页的主视觉来自**这一章自己的内容**，不要每页都铺同一张图。可以选：母题的一种变体（放大、拆分、局部特写）、这一章最关键的那张图解的预告、一句引文、一张满版的真实照片、一个关键数字。
- 例：第一章讲“检索”，章节页用注意力矩阵；第二章讲“多头”，章节页可以是同一个矩阵被拆成并排的几个小矩阵；第三章讲“位置编码”，章节页可以是一组正弦波。
- 在设计文稿的节奏表里，把每个章节页的主视觉写清楚，并检查相邻的章节页没有重复。

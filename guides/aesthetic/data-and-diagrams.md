# 数据图表、图解、公式与代码

> 何时读：页面上有图表、结构图、流程图、公式或代码时。

## 数据图表

- **标题就是结论**：“序列长度翻倍，代价变为四倍”，而不是“计算量对比”。
- **一个图表一个重点**：重点系列用强调色，其余用灰。没有重点的图表，不该放上来。
- **直接标注**：在线的末端或柱的旁边写系列名和关键数值，删掉图例。
- **少墨**：去掉边框、背景、3D、阴影；网格线用 hairline 色或者干脆不要；坐标轴只保留需要的那条。
- **数据可追溯**：数据写在 `content.md` 里（附来源），图表代码里的数字和它一致。示意数据必须在页面上注明“示意”。
- **数据和图形分别核对**：数值对了不等于图形对了。检查坐标轴的起点（柱状图从 0 开始）、比例和单位。
- 用原生图表（`k.chart`），用户可以在 PowerPoint 里编辑数据。只有原生图表做不到的形式（例：注意力热图、桑基图），才用形状逐个绘制，并在 `design.md` 里说明。

```js
k.chart('line', [{ name: 'O(n²)', labels, values }], { x, y, w, h, markers: true, format: '0' });
k.chart('bar', data, { ..., horizontal: true, labels: true, grid: false, valAxis: false });
```

可用类型：`bar`、`line`、`area`、`pie`、`doughnut`、`scatter`。饼图只在比较 2–3 个份额时使用。

## 图解配方：讲解页的图从哪里来

每一页都要有图（`principles.md` 第 4 条）；讲解页（`dense`）尤其要有一张图来承担机制（见 `anti-ai.md` 的“伪极简”）。先判断内容属于哪种关系，再选形式。下列形式都可以用原生形状绘制，并且都可以编辑。

| 内容里有…… | 图的形式 | 示例 |
|---|---|---|
| 一个东西变成另一个东西 | **变换流程**：输入 → 操作（标签）→ 输出，左到右排开；分叉表示一分多 | 词向量经 W_Q/W_K/W_V 得到 Q/K/V（`examples/attention` S04） |
| 一行元素之间谁连向谁、连得多强 | **弧线图**：元素排成一行，从一个元素向其他元素画弧（`k.arc`），弧的粗细和亮度编码强度 | it 对每个词的注意力（S03） |
| 两组元素之间的对应 | **二部连线**：两行（或两列）元素，线宽或颜色编码强度 | Q 与各词的 K（S05） |
| 两两之间的关系强度 | **矩阵 / 热图**：方格阵列，用色阶表示数值 | 注意力矩阵（S01） |
| 一组数值的大小对比 | **权重条**：横向细条直接排在条目旁边，数值写在条的末端 | softmax 权重（S05） |
| 向量、序列、内存、数组 | **单元条**：一行方格，用色阶表示数值，可以带下标 | Q/K/V 向量（S04、S05） |
| 规模怎样增长 | **同尺度并排**：同一种单元在同一尺度下画出几个规模，增长直接看得见 | 4×4 → 8×8 → 16×16 的注意力矩阵（S06） |
| 按时间发生的事 | **时间轴**：一条细线 + 刻度 + 贴近刻度的标注 | 技术演进、实验流程 |
| 层层包含、上下依赖 | **分层堆叠**：水平带状层，层名在左，细节在层内 | 网络协议栈、系统架构 |
| 整体由部分组成 | **剖面 / 展开**：整体在中央，部件用引线引出标注；或跨页放大 | 一个模型的模块 |
| 前后、有无、A 与 B | **并置对照**：两组对象用同一尺度，共用基线，差异处用强调色 | 优化前后的延迟 |
| 分支、分类、决策 | **树**：细线连接，节点就是文字 | 算法分类 |
| 周而复始 | **循环**：节点排成环，箭头沿环 | 训练循环 |

画图的要点：

- **用例子填实**：图里画的是具体的东西（“it 的向量”“animal 的权重 0.46”），而不是抽象的占位符。
- **一个主角**：图里最重要的那条路径、那个格子、那根条，用强调色；其余用灰阶。
- **复用整套的母题**：同一套演示里，向量永远是同一种单元条，连线永远是同一种细线。重复使用的结构写进 deck 的 `parts.js`（参考 `examples/attention/parts.js` 的 `vector()`）。
- **尺寸要够**：图解通常占安全区的 40–60%。
- **文字是标签**：名词、数值、一句话的说明贴在图的对应位置，不另起一列要点。

## 结构图与流程图

- 关系必须真实：箭头方向、层级、包含关系不能为美观而改变。
- 节点首选**文字本身**，而不是方框里的文字。确实需要容器时，用细线框或极浅的底色，不加圆角阴影。
- 连线用 0.75–1.5pt 的细线；重点路径用强调色并加粗。
- 复杂的图分层展示：先整体，再局部（跨页 Morph），不要一页塞满。
- 每个节点、连线和标签都是独立的原生对象，方便编辑和做动画。需要跨页延续的对象，给它起 `name`。

## 公式

- 简单公式用文本加 Unicode 符号排版，使用 `STIX Two Math` 字体。上下标用 run 的 `superscript` / `subscript`：`['softmax( QK', { text: 'T', superscript: true }, ' / √d', { text: 'k', subscript: true }, ' ) V']`。不要用上下标的 Unicode 字符（`ᵀ`、`ₖ`）：STIX Two Math 里没有它们，PowerPoint 会换成别的字体显示，`make.js` 会报缺字。
- 复杂公式（分式、矩阵、求和上下限）：目前引擎不能生成可编辑的 OMML 公式。可以把公式拆成多个文本对象手工排版，或者渲染成高分辨率 PNG 插入（并在备注中保留 LaTeX 源码）。这一点要在 `design.md` 中说明。
- 公式旁边用一两个标注解释关键符号，而不是在下面写一段文字。

## 代码

- 等宽字体（`Menlo`），16–20pt，一页最多 12–15 行。只展示讲解需要的那几行。
- 当前讨论的行用强调色或浅色底标出，其余行用 graphite 色。
- 不放 IDE 截图；不加“窗口装饰”（红黄绿三个圆点）。

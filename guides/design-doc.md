# 设计文稿

> 何时读：阶段 2，根据 `content.md` 写 `02-design/design.md` 时；以及用户要求修改设计文稿时。

设计文稿把内容翻译成**可直接制作的逐页方案**，同时定义整套的设计系统。它要具体到：制作者不需要再做任何审美决定，就能把每一页做出来。

模板：`templates/design.md`。

## 写之前

1. 读 `content.md` 全文和 `project.md`（尤其是决策记录里的偏好和禁令）。
2. 读 `aesthetic/principles.md` 和 `aesthetic/anti-ai.md`。确定字体、颜色和构图时，再读 `typography.md`、`color.md` 和 `composition.md`。
3. 先想清楚**艺术方向**，再动手写逐页方案。

## 艺术方向：要具体

艺术方向不是一个风格名称（“简约商务风”“科技风”）。它要回答：

- **参照什么**：1–3 个真实的参照对象（某本杂志、某种海报传统、某场发布会、某位设计师），并说明从中借用什么（例：“借用 Monocle 的衬线大标题和满版照片，不借用它的密集栏目”）。
- **三个情绪词**：例如“安静、精确、有温度”。
- **反参照**：明确不要什么（例：“不要科技蓝渐变，不要卡片”）。
- **主视觉策略**：这套演示的视觉主角主要是什么？照片？原生图解？排版本身？数据？
- **一个整套的母题**（可选）：一个在不同页面以不同形式出现的视觉元素（例：注意力矩阵在封面是主图，在第 8 页变成被拆解的对象）。

## 逐页方案：要能直接制作

每页写清楚：

- **页面 ID 与角色**：`S07 · dense · 数据焦点`。
- **核心信息**：观众看完这页应该记住的一句话。
- **主角**：页面上最大、最先被看到的是什么。
- **画面文字**：逐字写出要上屏的每一段文字（标题、标注、数字、来源）。这是定稿文字，不是提示。
- **构图**：主角的位置和大致比例（占哪几栏、上下位置）、阅读路径、留白在哪里。
- **视觉元素**：图解里的具体对象和关系；图表的类型、数据和重点系列；图片的来源和裁切。
- **图解**（dense 页必填）：用 `aesthetic/data-and-diagrams.md` 的“图解配方”选定图的形式，并写清图里画的是哪个具体的例子。再问一句：不看讲稿，观众能从这张图上学到什么？答不出来，就重新设计这一页。
- **动态**：转场方式；如果属于 Morph 序列，说明哪些对象延续、怎样变化。
- **备注要点**：演讲者要讲的内容。

## 结构层与章节页

读 `aesthetic/composition.md` 的“结构层”和“章节页”两节，然后在设计文稿里写明：

- 这套演示用哪几种结构元素（导航框架、引导线、尺寸线、刻度对位、色块分区、纸张颗粒），各自用在哪类页面。
- 每个章节页的主视觉分别是什么。章节页之间系统一致，主视觉各不相同。

## 节奏表

用一张表列出全部页面：ID、节奏标签（anchor / breathing / dense）、构图动作、主角、明暗。写完后检查：

- 连续 dense 页面不超过 3 页。
- 相邻页面不用同一种构图动作（Morph 序列除外）。
- 整套有 1–2 个视觉高潮。
- 章节页的主视觉互不重复。
- breathing 页（论断、引文、大数字）是有意的留白，占比 25–40%。不要把讲解内容做成 breathing 页：机制、过程、比较都属于 dense。

## 样张选择

选 3–5 页用于阶段 3 的参考样张，覆盖：

1. 封面或章节页（气质、字体、颜色）；
2. 最典型的普通内容页（大多数页面会长成它的样子）；
3. 最难的一页（复杂图解、数据或公式）；
4. 一页节奏页（论断、大数字、满版图或深色页）；
5. 如果有 Morph 序列，加上一组相邻的 2 页。

说明为什么选这几页。

## 待确认问题

无法从内容和用户偏好推断的问题，列在文末，并附上你的建议默认值。不要因为这些问题而停下不写。

## 修改设计文稿

用户提出修改时：

- 只改用户指出的部分，并检查它对节奏表和其他页面的连带影响。
- 用户的审美偏好要同时记进 `project.md` 的决策记录。
- 改完后简要说明改了哪些地方。

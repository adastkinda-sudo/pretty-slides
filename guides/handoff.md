# 跨 Agent 交接规范

适用于 Pretty Slides 框架开发。Codex 与 Claude 各自在独立 worktree 和任务分支中工作，以 Git 提交作为交接记录。

## 交接范围

同步框架代码、流水线逻辑、规范、模板、Skills，以及用于框架验证的仓库内示例。

`projects/<slug>/` 中的具体演示、个人素材和生成产物不属于框架交接范围。双方的实际生成在各自 worktree 中独立进行，不接续或复制对方的演示项目。

## 何时查看对方改动

仅在以下情况查看：

- 用户明确提醒对方已完成改动，要求查看或同步。
- 准备调整项目结构或整体逻辑，例如目录组织、流水线阶段、引擎接口、共享数据格式或执行规则。

普通对话、局部小功能、小范围修复和文字勘误直接围绕当前任务工作，不额外查看对方差异或同步分支。不在每轮对话开始时扫描对方进度，也不自动判断是否发生了 Agent 切换。

按影响范围判断，而不是按文件类型判断：调整 AGENTS.md、Skill 或 guides 中的流水线关口与核心执行规则，也属于整体逻辑调整。

## 完成一个独立改动

完成必要验证并审阅差异后，按带 scope 的 Conventional Commits（约定式提交）规范提交，并推送到自己的任务分支。只提交本次任务的相关改动；没有文件改动时不创建空提交。

```text
feat(engine): add slide selection support
fix(render): correct page image ordering
docs(workflow): clarify reference approval rules
```

提交说明保持简洁，不强制固定正文模板。必要的验证结果、限制或阻塞在提交正文或交付消息中简要说明，不额外维护交接日志、状态文档或聊天副本。

## 查看与同步

触发交接后：

1. 检查自己的工作区状态，读取对方尚未同步的相关提交和差异；根据当前任务追查必要依赖。
2. 判断哪些改动需要引入。以提交为单位同步必要改动，保留可追溯的来源；读取对方进度本身不要求合并代码。
3. 对同步后的改动做相应检查，简要报告引入的提交、验证结果及实际阻塞。

同一仓库的 worktree 可直接读取对方本地分支的记录；对方在另一克隆或机器上工作时，按需获取远程分支。交接文件如有必要，也可直接从另一分支读取。

保留双方未提交改动，不通过复制或覆盖工作目录同步代码，不擅自接管对方 worktree。提交和推送不代表授权合并主分支、发布或部署。

# 渲染自查

> 何时读：每次渲染之后、把结果给用户看之前。

源代码不是视觉证据。每次构建后，都要用 Read 工具打开渲染图（`renders/Sxx.png`），**亲眼看过**再下结论。

## 顺序

1. **看 QA 输出**：`✗` 硬问题全部修掉。
2. **看缩略总览**（`renders/_contact.png`，整套构建时生成）：统一性、节奏、有没有某一页突然变粗糙或变拥挤。
3. **逐页看大图**，按下面的清单检查。
4. 修改，然后只重新渲染受影响的页面（`--only`）。
5. 默认最多自修 **2 轮**。剩下的问题如果属于设计判断，交给用户，并附上具体建议。

## 硬规则（命中就修）

| # | 问题 | 怎么修 |
|---|---|---|
| H1 | 元素超出画布（不是有意出血） | 移回画布内，或者标 `bleed: true` |
| H2 | 文字溢出文本框、被截断、意外换行、出现孤字 | 调整框宽、措辞或换行位置；不要缩小字号来解决 |
| H3 | 文字与文字、文字与图形意外重叠 | 重新排位置 |
| H4 | 对比度不足、文字压在复杂图像上看不清 | 换成 theme 里更深的颜色；在图像上加一块纯色底 |
| H5 | `design.md` 里要求的元素缺失 | 按设计文稿补上 |
| H6 | 字体被替换（渲染出来的字形明显不对） | 改用已安装的字体，并更新 theme |
| H7 | 数据和图形不一致：数值、比例、坐标轴起点 | 回到数据源修正 |
| H8 | dense 讲解页没有图形主体，只有名词和文字（“伪极简”） | 按 `data-and-diagrams.md` 的图解配方补一张表达机制的图；属于设计层面的改动，按设计文稿补写这一页的方案 |
| H9 | 单行标签的文本框宽度余量不足（PowerPoint 的字体度量与预览不同，会意外折行） | `nowrap: true`，或把框加宽到 1.15 倍以上 |

## 软规则（明显不好才动）

| # | 问题 | 方向 |
|---|---|---|
| S1 | 主角不是最显眼的元素 | 放大主角，或者弱化抢眼的次要元素 |
| S2 | 对齐漂移：应该对齐的边缘相差 > 0.05 英寸 | 吸附到网格 |
| S3 | 留白零碎，或某处过挤 | 把空白合并成大块 |
| S4 | 强调色出现超过 2 处 | 只留最重要的一处 |
| S5 | 命中了 `aesthetic/anti-ai.md` 禁用清单中的任何一条 | 按清单的“改用”一栏修改 |
| S6 | 相邻页面的构图或密度雷同 | 在不违背 `design.md` 的前提下调整，或者向用户提出 |
| S7 | dense 页的图形主体太小（不到安全区的 25%），或页面整体空洞 | 放大图解，让文字围绕图解做标注 |

拿不准的时候，就不动。少修胜过来回改。

## 不准动

自查修复**只修执行偏差**，不重新设计：

- 不改 theme 里的颜色、字体和字号层级（这些是用户认可过的设计）。
- 不改页面的构图动作、不增删内容。
- 不改其他页面。

如果问题必须靠这些改动才能解决，就停下来，把它写成给用户的建议：哪一页、什么问题、建议怎么改。

## 交给用户时

- 给出 pptx 路径和缩略总览（或相关页面的渲染图）。
- 一句话说明这次做了什么，以及仍然存在的问题。
- 如实区分：“已渲染检查”“QA 启发式检查”“未验证”（例如 Morph 的实际播放、Windows 上的字体）。

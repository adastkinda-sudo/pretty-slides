## 1. 视觉语言的来源

### 主题自己的审美（第一来源）

这套演示的主角是一个把审美当作信仰的人。设计的出发点不是“乔布斯的故事像什么”，而是：**如果乔布斯来做这套关于他自己的演示，他会怎样做？**他会用他做产品的方式来做。下面每一条原则，都直接决定了这套演示的一部分。

| 他的原则（content.md「人物」） | 在这套演示里变成什么 |
|---|---|
| **简单是最终的复杂**（1977） | 每页只放一样东西。没有卡片、图标、要点列表、装饰。一页上只有一个主角、一句话、少量注释 |
| **专注就是说不**（1997） | 一套颜色：灰阶 + 物件自己的材料色 + 一种有含义的蓝。一个字体系统的两种声音。凡是不承载信息的东西都不放 |
| **看不见的地方也要做好**（父亲的篱笆、Mac 机箱里的签名） | 物件按真实比例精确绘制（圆角、屏幕比例、厚度都依据真实产品）；对齐、字距、中西文混排、标点按印刷品的标准做；备注写满，演讲者看到的那一面也要好 |
| **设计是它怎样工作** | 每一个物件都画出“它怎样工作”的那一部分：Mac 屏幕上按比例的字距、iPod 的滚轮、2×2 的格子、iPhone 唯一的按钮。物件不是插图，而是讲解本身 |
| **技术与人文的十字路口** | 字体分两种声音：无衬线（PingFang SC / Helvetica Neue）讲事实、年份、产品，是“技术”；衬线（Songti SC / Hoefler Text）只用于他本人的话，是“人文”。两种声音在每一页相遇 |
| **一次只说一件事**（他的发布会） | 页面像他的发布会一样逐步揭示：先出现物件，再出现那一句话；Morph 让同一件东西在页面之间移动、变形——像他把 iPod 从口袋里拿出来 |
| **好的设计属于每一个人**（Eichler） | 清楚胜过炫技：后排观众也能读出每一个字；没有需要“看懂”的视觉谜语 |
| **空的房间**（1982） | 大面积的留白不是“没做完”，而是他的选择：宁可空着，也不放不够好的东西。S12（被开除）是一整页的空 |

### 意象

**他一生的点，就是他做出的一件件东西；把它们连起来的，是同一种审美。** 整套演示是一间“作品陈列”：每一页把一件东西（或一件塑造了他的东西）放在干净的光里，像 Apple 对待自己的产品一样对待它。点，就是这些物件；线，是回头才看得见的联系。

### 主题自己的形状与结构

- **物件**：篱笆（正面 / 背面）、Eichler 住宅、一个衬线字母、Apple I 电路板、Apple II、施乐的图形界面、Macintosh（正面 / 机箱内壁）、NeXT 立方体、iMac、iPod、iPhone、2×2 格子、十字路口的路牌。全部可以用原生形状画出。
- **时间**：1955–2011 共 56 年的一条线，物件按真实年份落在线上。
- **汇合**：三台设备 → 一台设备（发布会原话的结构）；四个来源 → 一件作品。

### 材料与颜色

- Apple 自己的中性色：页面的浅灰白、文字的近黑、次要文字的中灰、细线的浅灰（Apple 网站沿用多年的那组中性色）。
- 物件自己的颜色：Apple II 和 Macintosh 的米色塑料、NeXT 的黑色镁合金、iMac 的邦迪蓝、iPod 的白色聚碳酸酯、iPhone 的黑色玻璃与铝。
- 唯一一种带含义的颜色：**链接蓝**——网页上“这里连向别处”的颜色。在这里它只表示“回头才看得见的联系”。它也呼应 S13：第一个网页浏览器就诞生在乔布斯的 NeXT 上。

### 符号系统

产品说明的语言：精确的尺寸线（“1 ft”“11.6 mm”）、标注引线、规格小字。它们不是装饰，而是“看不见的地方也要做好”的证据。

### 母题（以及它在不同页面上的形态）

**一条生命线**（1955–2011）+ **线上的物件**：

- S01–S02：生命线是主图，只有点。
- S03–S22：生命线缩到页面底部，成为导航（讲到哪一年了）。当前这一页的点是实心近黑，讲过的点是中灰，没讲到的点是空心。
- 物件页：生命线上方是这一页的物件，放大到占画面的 40–60%。
- S23：生命线回到主图尺度，所有物件按年份缩小站回线上，蓝色的联系线全部可见——一排“产品阵列”，也是他的一生。

## 2. 候选方向

三个方向都从他本人的审美出发，但在气质上拉开：一个是他做的**产品**，一个是他讲东西的**舞台**，一个是他生活的**房间**。

### 方向 A：作品陈列（推荐）

- **一句话**：像 Apple 对待自己的产品那样，把他一生的每一个点画成一件放在干净光线里的东西。
- **情绪词**：精确、明亮、克制。
- **体现了他的哪几条原则**：简单（每页一件东西）；看不见的地方也要做好（物件按真实比例、尺寸线、机箱内壁）；设计是它怎样工作（物件画出工作方式）；技术与人文（两种字体声音）；Eichler（明亮、清楚，属于每一个人）。
- **参照**：
  - Apple 在他主持下的产品页与包装（约 2001–2011）：浅灰白底、居中放大的产品、短句标题、极小的规格字——借用“一件产品占满注意力”的构图和中性色体系。
  - Dieter Rams 时期的 Braun 产品图册：精确的正视图、细线标注、大量留白——借用物件的画法（正视图、单线、无透视）。
  - Apple 产品技术规格页：尺寸线与规格表——借用尺寸线和标注的语言。
- **色彩 / 字体 / 构图 / 图像**：浅灰白（`F5F5F7`）带极细颗粒，物件背后一束无边缘的“摄影棚光”（`k.light`，白色）；近黑文字；物件用材料色；只有链接蓝表示联系。中文 PingFang SC（苹方，Apple 的中文字体）+ Helvetica Neue（初代 iPhone 的界面字体）；他本人的话用 Songti SC + Hoefler Text（1991 年随 Apple System 7 发布的衬线字体）。物件页居中（单一焦点，正是他“一次只放一样东西”的做法）；讲解页非对称。所有物件用原生形状绘制成正视图，不用照片。
- **适合的场合与风险**：适合任何分享会，浅色在投影上稳定，物件即讲解。风险：①物件画得不够精确，就会像剪贴画——必须按真实比例画，宁少勿粗；②浅灰底 + 苹方 + Helvetica 容易显得“普通”（用户在 attention 项目里说过系统默认字体“太普通”）——对策是尺度的戏剧性（200pt 的 UltraLight 数字、占半页的物件）、两种字体声音的对比、以及只有这个人物才有的物件；③居中构图过多会单调——物件页居中，讲解页、引文页、数字页各用不同的构图动作。

### 方向 B：发布会

- **一句话**：用他自己的发布会来讲他的一生：一个舞台，一次只亮出一样东西。
- **情绪词**：戏剧、自信、揭示。
- **体现了他的哪几条原则**：一次只说一件事（他的发布会）；简单（每页的主文字不超过一句）；设计是它怎样工作（发布会上演示的是“怎样用”）。
- **参照**：2007 年 iPhone 发布会、2008 年 MacBook Air 发布会的屏幕——借用深灰渐变的舞台、巨大的产品、细字重的白色大字、逐步揭示；电影片头——借用镜头式的连续运动。
- **色彩 / 字体 / 构图 / 图像**：舞台为冷石墨色（`1E1F22`，细颗粒、四角略暗、顶部略亮），不是纯平的黑；文字白（`F5F5F7`）与银灰（`A1A1A6`）；联系线用亮蓝（`2997FF`）。字体 Helvetica Neue Thin / Light + PingFang SC，他的话同样用 Songti SC + Hoefler Text。物件放在舞台中央，下方一道淡淡的倒影（同一形状翻转、高透明度）。
- **适合的场合与风险**：最像他本人站在台上，适合大屏、正式的分享。风险：①**整套深色，与用户要求“与 attention 的暗场明显不同”冲突**——冷灰、无琥珀、无热图，但“暗底 + 被照亮的主体”的结构相同；②倒影属于“效果”，用多了会显得廉价；③深色投影在明亮会议室里发灰。

### 方向 C：空房间

- **一句话**：1982 年那间几乎空着的客厅：一面墙、一块地板、一束从窗外照进来的光；他一生的每个点，是房间里唯一的那件东西。
- **情绪词**：安静、内省、温暖。
- **体现了他的哪几条原则**：禅与极简（空的房间）；宁可空着也不放不够好的东西；简单（每页只有一件东西）。
- **参照**：Diana Walker 1982 年的照片（只借用“空房间 + 地板 + 一件东西”的构成，不复制照片）；日本建筑摄影（安藤忠雄、谷口吉生）——借用墙面、地面、光的三分构成；京都寺院的留白。
- **色彩 / 字体 / 构图 / 图像**：墙为暖白灰泥（`F1ECE3`），下方约 22% 是浅橡木地板（`E3D5BC`，两三条细木纹线），墙地交界一条踢脚线；窗光是一束暖色的 `k.light`，随页面推进从左向右移动（一生从早晨走到黄昏）。文字写在墙上：Songti SC 标题 + PingFang SC，他的话用 Hoefler Text。物件安静地放在地板上，细线、平涂。
- **适合的场合与风险**：气质最“人”，适合小场合、偏人文的分享。风险：①讲解页（2×2、汇合、字距对照）放进“房间”里会显得别扭——图解只能挂在墙上；②房间里的物件需要轻微的立体感，原生形状不易画好；③暖白 + 衬线，容易滑回 v1 那种“米白纸 + 一种强调色”的安全风格。

**推荐与理由**：推荐 **A 作品陈列**。

1. 它最直接地回答了“如果乔布斯来做”：他一生的点就是他做出的东西，而他对待东西的方式（简单、精确、连内部都要好）正好是这套演示的做法。审美原则不是贴在页面上的口号，而是页面本身的做法。
2. 物件即讲解：Mac 屏幕上的字距、iPod 的滚轮、iPhone 的一个按钮，都是“设计是它怎样工作”的证据，讲解页不会变成只有名词的伪极简。
3. 浅色、明亮、无暗场，与 attention 完全不同；B 与用户的约束冲突，C 的讲解页最难做。
4. Morph 序列最多、最自然：Apple I 的电路板装进 Apple II、Mac 转到机箱内壁、iPod 变成 iPhone、所有物件回到生命线上。

**已选方向**：**方向 C「空房间」**（2026-10-15，Agent 依用户授权，在 `03-reference/directions/_compare.png` 三方向并排对比后选定；理由见第 11 节）。第 4 节已按 C 改写。

## 4. 设计系统（当前为：方向 C 空房间）

> 2026-10-15 由 Agent 依用户授权选定方向 C（理由见第 11 节）。本节依据 `03-reference/directions/C/` 的探针实现（`theme.js`、`parts.js`、`room.json`、`room.py`）写成。方向 A 的设计系统见项目 git 提交 `c8a1d6b`。

### 世界

整套演示是**同一间房间**：1982 年他那间几乎空着的客厅。一面暖白灰泥墙、一条白色踢脚线、一块浅橡木地板、左墙上一扇看不见的窗。一台低机位的相机（像坐在地板上看房间）。每一页，房间里只放一件东西；文字和图解写在墙上；生命线是地板上的一条缝。

**太阳是时间。** 窗外照进来的阳光随页面推进，从早晨走到黄昏——他的一生也是这样一天。阳光落在每一页的主角上，物件在墙上和地板上投下影子。光由 `room.py` 依 `room.json`（共享的相机与房间）和 `rooms/<ID>.json`（这一页的太阳时刻、光斑落点与物件）逐页算出，是真实的光：有窗棂的影子、柔和的半影、物件的接触阴影。怎样做一页见 `03-reference/README.md`。

| 页 | 时刻 | 光 |
|---|---|---|
| S01 | 清晨 | 低而暖的长方形光斑，带一道窗棂影，落在名字上 |
| S02–S06（来源） | 早晨 | 光斑渐高、渐白 |
| S07–S11（车库） | 上午 → 正午 | 最白、最清楚；S10–S11 正午 |
| **S12（30 岁）** | **阴天** | **没有太阳**：房间第一次处在平的阴影里——全片最低点 |
| S13–S15（荒野） | 午后，云散 | 光回来，偏淡 |
| S16–S20（回归） | 下午 → 金色时刻 | 越来越暖、越来越长；**S20 最强的金色光** |
| S21–S22（回头看） | 日落 → 黄昏 | 低、橙、很淡、很长 |
| S23 | 最后的光 | 一道横贯房间的低光，落在整排物件上 |

### 网格与空间

- 边距：左右 0.9 in，上 0.7 in，下 0.55 in。12 栏，栏距 0.22 in。
- **房间的固定几何**（`room.json`）：墙地交界（踢脚线顶）y ≈ 5.85 in，所有页面不变——这是“同一间房间”的锚。
- **物件**站在地板上，底边落在 y ≈ 6.0–6.3 in；高度按页面需要取 2.5–4.6 in（相当于相机走近或退后），占画面高度 40–60%。小物件（字母、iPod、iPhone）不按与 Mac 的真实相对尺寸缩小——相机走近了；但每个物件自身的比例按真实产品。
- **墙上的字**：标题在左上 `k.col(1)`，y ≈ 1.0 in；他的话在标题下方或物件另一侧；图解直接画在墙上。
- 引文页：文字写在墙上光斑里。

### 视觉语言

- **物件**（`parts.js`，每个物件一个函数，正视图，按真实比例）：受光来自左上；亮面、侧面、背光面三档；细的暗色描边只在物件与亮墙对比不足时使用。物件的真实尺寸写在它自己的 `objects/<name>.js`，位置登记在 `rooms/<ID>.json`，`room.py` 据此算出它的影子——物件与影子永远对得上。不画任何标志和商标。
- **墙上的图解**：用 graphite 0.75–1pt 的细线直接画在墙上（像建筑师在墙上画的草图，或他在白板上画的 2×2）；节点就是文字。重点处由阳光照亮。
- **联系线**：link 蓝。在地板上（导航尺度）是扁弧（弧高逐条给定，`parts.LINK_H`：按跨度排序，共端点的弧至少差 0.1 in，最高 0.72 in；见第 11 节整合），之前出现过的 1pt，本页新出现的 2.25pt；在墙上（S23 主图）是高弧。
- **引线**：seam 色 0.75pt 细线，末端小点；水平或竖直。
- **尺寸线**：工程图式细线 + 两端短竖线，只标真实规格。
- **图片**：除 `room.jpg` 与每页的 `sun-SXX.png` 外不用图片；物件全部原生绘制。

### 结构层

- **生命线（导航）**：地板上离墙第三条板缝（y = 6.95 in），横贯房间；14 个点像钉头：讲过的 stone 实心，当前 ink 实心放大，未讲到的 hairline 空心。年份与事件标在线下（year + label）。Morph 名固定（`life`、`ld-1955`……）。S01、S23 的生命线是主图，其余页是导航。
- **部标记**：左上 label（`二　车库`），右上 year（本页年份）。不设页码。每部第一页把部标记放大一次（lead 尺度、ink）。
- **太阳**：每页一张 `assets/sun/<ID>.png`（Morph 名 `sun`，放在房间之上、物件之下）+ 一束微弱的 `k.light`（暖色反光）。
- **底色**：`assets/room.jpg`（整套同一张）。

### 动态语言

- **默认转场**：整套 Morph（1200 ms），S01 为 `none`。太阳（`sun`）、生命线、物件同名延续：翻页时阳光在墙上移动，像时间在走。S12 阳光消失；S13 阳光回来。
- **页内出现**：先物件（或墙上图解的结构），再那一句话，最后联系线。每页 1–3 次单击。
- **Morph 序列**：与第 4 节 A 版相同的物件序列仍然成立（S07→S08 电路板进机身、S10→S11 Mac 让到一边露出内壁、S13→S16 立方体、S19→S20 iPod 变 iPhone、S22→S23 拉远成全景）。
- **未验证**：Morph 与页内动效、阳光图片在两页之间的过渡（预计边移动边淡入淡出），须在 PowerPoint 中放映确认。

### 2026-10-15 样张深化（03-reference：S01 S10 S11 S12 S20）

由阶段 3b 会话制作（Agent 按用户授权自行把关审美）。下面是制作中做出的、上文没有写明的决定；第 4 节已同步了其中涉及设计系统的几处（光由 `rooms/<ID>.json` 算出、number 的数字样式、物件登记方式、地板弧高、阳光文件路径）。

**系统（为并行补页而模块化）**

- `room.json` 只放整套共享的房间几何；每页的太阳与物件放在 `rooms/<ID>.json`；每个物件一个文件 `objects/<name>.js`（真实尺寸 `real` + 画法 `draw`），`parts.place(k, id)` 按 `rooms/<ID>.json` 画出它，`room.py` 读同一个 `real` 投影子。`python3 room.py S10` 只算一页。并行时用 `lane.sh` 各自构建渲染。全部写在 `03-reference/README.md`。
- **太阳时刻函数** `sun_at(time)`（`room.py` 的 `SUN_KEYS`）：时刻 → r（光朝后墙的程度：正午大、影子短；早晚小、影子被甩远）、s（下落坡度）、颜色、强度、半影、环境光。每页只写 `time` + `aim`（墙上光斑的中心与大小），窗洞由程序反算。23 页的建议时刻与光斑落点见 README 第 4.3 节。
- **新增“环境光”（ambient）**：饱和的暖色光斑不可能比暖白墙更亮（正常叠加下，金色光斑看起来像一块橙色的漆）。所以从下午起房间其余部分轻微变暗（金色时刻 10%，黄昏 15%），光斑才读得出是光——和照片的曝光一样。金色时刻的颜色也相应提亮（`FFE2B4`）。
- **物件材料色写在物件文件里**，theme.js 只管房间、文字与屏幕内文字（mac* 等令牌从 theme 移到 `objects/mac.js`）。物件正面不在阳光里时，`tone()` 把材料色压暗 20%（S11 的 Mac 前半）。
- **需要看见深度的物件用房间的真透视画**（`parts.project` / `worldBox`，与 room.py 同一台相机）：打开的机箱必须看得见内壁才读得出是“壳”。由此推出：NeXT 立方体（S13–S16）在这间房间里也画真透视（正面 + 朝消失点一侧的侧面），**看不到顶面**（相机眼高低于 1 ft 立方体的顶），不画第 7 节写的等轴测。

**地板**：探针的木纹是一张横向拉长的噪声，像拉丝金属。改为按地板坐标生成的宽板平切橡木：每块板有自己的色调与冷暖、按树的锥度画出的“教堂纹”（拱形年轮）、约 30% 的板为直纹；板的两端有对缝（按透视收向消失点）；细的导管纹沿木纹时有时无；年轮细到一个像素以下时淡出成板的平均色，不产生摩尔纹。

**S01**：名字从 72pt 放大到 88pt（第 4 节允许封面到 88；72 / 88 / 104 并排比较后选定）。清晨的光斑相应加宽（墙上 x 1.4–9.6 in），窗棂移到 0.78 处，名字整个落在左边那格光里，不被窗棂影切开。

**S10**：沿用探针构图（标题与他的话在左，Mac 居中略偏右，屏幕右侧两条引线标注“等宽 / 按比例的字距”），联系线标签改为“十年后，连上了”。正午光斑的上沿留在画面内，墙上看得见 Mac 的影子。

**S11 ★ 机箱里的签名**：
- 构图：Mac 的前半（离墙近、`d_mm` 190）站在左边；打开的后壳站在右边、**离镜头更近**，所以更高（4.4 in 对 3.75 in）——这是房间里真实的透视，不是两种比例。开口朝向我们，看得见右内壁、内底、内壁上的加强筋、螺丝柱、把手凹槽背面、散热槽和 I/O 面板。

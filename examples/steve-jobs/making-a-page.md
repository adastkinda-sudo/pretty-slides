# 空房间 · 怎样做一页

> 给补页的会话：读这份手册和 `docs/design.md`（第 4 节设计系统、第 7 节你这一页的方案、第 11 节样张回写）就够了。
> 先看一遍五张样张的代码和渲染图：`slides/S01 S10 S11 S12 S20`、`renders/`。它们是已定稿的视觉标准，照着它们的做法做。

整套演示是**同一间房间**：一面暖白灰泥墙、一条白色踢脚线、一块宽板橡木地板、左墙上一扇看不见的窗。每一页房间里只放一件东西；字和图解写在墙上；生命线是地板上离墙第三条板缝。**太阳是时间**：从 S01 的清晨走到 S23 的黄昏。阳光和影子不是手画的，而是 `room.py` 按真实几何算出来的，所以物件和它的影子永远对得上。

## 1. 目录

| 文件 | 是什么 | 谁能改 |
|---|---|---|
| `room.json` | 共享的房间：相机、地板、踢脚线、窗所在的墙 | 不改（改了整套的房间都变） |
| `room.py` | 渲染房间（`assets/room.jpg`）和每页的阳光（`assets/sun/<ID>.png/.json`） | 不改，除非协调好 |
| `rooms/<ID>.json` | **这一页的房间**：太阳（时刻 + 光斑落点）+ 站在房间里的物件 | 这一页的会话 |
| `objects/<name>.js` | **一个物件一个文件**：真实尺寸 + 画法 | 新物件由创建它的会话写；已有的不改 |
| `parts.js` | 共享部件：阳光、物件注册、生命线、部标记、引线、尺寸线、墙上笔触 | 不改，缺什么先在页面里写，报告里提出 |
| `theme.js` | 颜色、字体、字号（规格锁） | 不改 |
| `slides/<ID>-<短名>.js` | 一页 | 这一页的会话 |
| `deck.js` | 页序 `ORDER`；还没写的页自动跳过 | 由主会话改 |
| `lane.sh` | 并行时只构建、渲染自己的几页 | — |

## 2. 新增一页：六步

以 S13（NeXT 立方体）为例。

**① 读方案。** design.md 第 7 节 S13：核心信息、画面文字、构图、图解、动态、备注要点。第 4 节的时刻表告诉你这一页是几点。

**② 写 `rooms/S13.json`。**

```json
{
  "_": "S13 NeXT · 午后，云散：光回来，偏淡。立方体站在地板中央。",
  "sun": { "time": 13.6, "strength": 0.75, "aim": { "x": 7.4, "y": 3.6, "w": 5.6, "h": 4.6 } },
  "objects": [
    { "use": "next-cube", "cx": 6.8, "baseY": 6.25, "h": 3.2 }
  ]
}
```

**③ 物件。** `objects/` 里已有的直接用（见第 5 节）；没有的，新建 `objects/next-cube.js`（约定见第 5 节）。

**④ 算阳光。** `python3 room.py S13`（只算这一页；**不要**不带页号地跑，也不要加 `--room`）。终端会提示物件正面有多少在阳光里：

- `next-cube front face 100% in the sun` 之外的数字说明光没完全照到它。主角要照到：调 `aim`（见第 4 节），重跑。
- 想快速看光斑和物件的位置关系：`python3 room.py S13 --preview /tmp/x`，看 `/tmp/x/preview-S13.png`（物件位置画成方框）。

**⑤ 写 `slides/S13-next.js`**（模板见第 6 节），然后构建渲染：

```bash
./lane.sh s13 S13            # 并行时用：渲染到 _lanes/s13/renders/S13.png
node ../../engine/make.js .  --only S13   # 只有你一个会话在做时也可以直接用（在本目录里）
```

**⑥ 亲眼看图**（Read 打开 png），按 `guides/production/review.md` 自查，修到满意。Morph 序列的相邻页放在同一个 lane 里一起看。

## 3. `rooms/<ID>.json`

```jsonc
{
  "_": "一句话：这一页的时刻和光（写给人看的）",
  "sun": {
    "time": 13.6,                 // 时刻（小时），由 sun_at(time) 换算出方向、颜色、强度、半影、环境光（第 4 节）
    "aim": { "x": 7.4, "y": 3.6, "w": 5.6, "h": 4.6 },  // 墙上光斑的中心与大小（幻灯片英寸）
    "mullions": [0.78],           // 可选：竖窗棂，在光斑宽度上的位置（0–1）；"transoms" 同理（横档）
    "strength": 0.75,             // 可选：覆盖时刻的默认值（叙事需要时：S13–S15 偏淡、S18 很淡）
    "color": "FFE2B4", "ambient": 0.1, "soft": 0.05, "r": 0.8, "s": 0.16   // 可选：其余默认值也都能覆盖
  },
  // 阴天（只有 S12）：  "sun": { "sky": "overcast", "shade": 0.075 }
  "objects": [
    { "use": "mac", "cx": 2.3, "baseY": 6.05, "h": 3.75 },          // 物件正面在幻灯片上的中心 x、底边 y、高
    { "use": "mac-case", "cx": 9.25, "baseY": 6.45, "h": 4.4 },
    { "use": "next-cube", "id": "cube-small", "morph": "obj-cube", "cx": 11.6, "baseY": 6.3, "h": 0.7, "d_mm": 305 }
  ]
}
```

- `use`：`objects/<use>.js`。同一页放两个同样的物件时，用 `id` 区分（`place(k, 'cube-small')`）。
- `morph`：覆盖 Morph 名（默认 `obj-<use>`，物件文件也可以自己声明，如 iPhone 的 `obj-pocket`）。
- `d_mm` / `w_mm` / `h_mm`：覆盖真实尺寸（例：S11 里 Mac 的前半只有 190 mm 深）。
- `shadow: false`：不投影（贴在墙上的东西）。
- `lean: 10`：靠墙斜放的板子（`apple1`）。`room.py` 自己把板子与墙之间的楔形算成 10 级阶梯盒子（`lean_boxes`），影子上窄下宽；受光比例按板子的斜面计算。S07、S23 用它。
- 受光比例（`assets/sun/<ID>.json` 的 `lit`）按 `id`（没有 `id` 时按 `use`）记录，与 `place(k, id)` 一致；不需要再写 `name`。
- **`baseY` 决定物件离墙多远**：baseY 越大，离镜头越近、离墙越远。`baseY` 和 `h` 一起决定物件的真实大小（同一个物件，离镜头近就显得大——S11 的后壳比 Mac 前半大，就是因为它站得更靠前）。物件的背面不能进墙：`room.py` 会报 `its back is … behind the wall`，把 baseY 调大。
- 物件底边一般在 `baseY` 5.9–6.5；生命线在 6.95，物件和它的标注不要压到 6.85 以下。

## 4. 太阳

### 4.1 时刻 → 参数：`sun_at(time)`

`room.py` 里的 `SUN_KEYS` 是关键帧，中间线性插值（`python3 room.py --times` 打印这张表）。阳光沿 d = (1, −s, −r) 前进：从左墙的窗向右、向下 s、朝后墙 r。

| 时刻 | r | s | 强度 | 半影 in | 环境光 | 颜色 | 读起来是 |
|---|---|---|---|---|---|---|---|
| 6.5 | 0.75 | 0.14 | 0.90 | 0.060 | 0.03 | `FFE9C9` | 黎明：很低、很暖 |
| 7.0 | 0.90 | 0.22 | 1.00 | 0.050 | 0.02 | `FFF0D6` | 清晨（S01） |
| 9.0 | 1.40 | 0.25 | 0.95 | 0.042 | 0.01 | `FFF6E8` | 早晨：渐高、渐白 |
| 12.0 | 2.60 | 0.28 | 1.00 | 0.032 | 0.00 | `FFFCF5` | 正午：最白、影子最短（S10–S11） |
| 14.5 | 1.60 | 0.25 | 0.80 | 0.040 | 0.02 | `FFF7E9` | 午后：偏淡 |
| 16.5 | 1.00 | 0.20 | 0.92 | 0.050 | 0.05 | `FFEDD0` | 下午：变暖、变长 |
| 17.3 | 0.80 | 0.16 | 1.00 | 0.055 | 0.10 | `FFE2B4` | 金色时刻：最强最暖（S20） |
| 18.2 | 0.65 | 0.11 | 0.80 | 0.070 | 0.13 | `FFD09C` | 日落：低、橙、长 |
| 19.0 | 0.55 | 0.08 | 0.65 | 0.090 | 0.15 | `FBBE88` | 最后的光 |

- **r** 小 = 光几乎贴着后墙横扫，影子被甩得很远（早晚）；r 大 = 光直冲后墙，影子短（正午）。
- **环境光（ambient）** 是房间其余部分变暗的程度。饱和的暖色光斑不可能比暖白墙更亮，所以傍晚的光之所以读得出是“光”，是因为房间暗了下去——和照片一样。
- 阴天（S12）：`{"sky": "overcast"}`，整间房一层平的冷灰，没有光斑。

### 4.2 光斑落在哪里：`aim`

`aim` 是**墙上**光斑的中心和大小（`x, y, w, h`，幻灯片英寸）。`room.py` 据此反算窗洞，所以你只管“光落在哪”。三件要知道的事：

1. **离墙越远的东西，照亮它的那块墙上光斑越偏右。** 深度 z 处被照亮的范围，是墙上光斑整体左移 z / r。低太阳（r 小）下这个偏移很大：S20 的 iPhone 离墙约 1 个单位，光斑就要比它向右多出约 1.35 in。物件正面没被照满时，把 `aim.x` 往右移、或把 `w` 放宽，或让物件靠墙一点（baseY 小一点）。
2. **光斑是斜的**：上下边每向右 1 in 下降 s in。
3. **主角要在光里**（视觉中心 = 光），**字可以在光里也可以不在**；引文页让光落在引文上（S01 的名字整个在左边那格光里）。

## 5. 物件：`objects/<name>.js`

一个文件一个物件，按东西命名（`next-cube`、`ipod`），不按页面命名。已有：

| use | 物件 | 真实尺寸 mm | 默认 Morph 名 | 返回的锚点 |
|---|---|---|---|---|
| `mac` | Macintosh 128K 正面 | 244 × 345 × 277 | `obj-mac` | `active`（屏幕可显示区） |
| `mac-case` | 打开的后壳，开口朝我们（真透视，签名示意） | 244 × 345 × 210 | `obj-mac-case` | `field`（签名区）、`at(u, v)`（内壁上的毫米坐标 → 幻灯片坐标） |
| `iphone` | 初代 iPhone 正面 | 61 × 115 × 11.6 | `obj-pocket` | `screen`、`home`、`edgeL/edgeR` |

约定：

```js
// objects/next-cube.js — 一句话：是什么、依据的真实尺寸
const { tone, poly, project, worldBox } = require('../parts');
const C = { face: '…', side: '…', … };          // 材料色写在这里（theme.js 只管房间和文字）
module.exports = {
  real: { w: 305, h: 305, d: 305 },              // 真实尺寸（mm）：room.py 用它投影子，必须真实
  morph: 'obj-cube',                             // 可选：默认 Morph 名
  draw(k, at) {                                  // at = rooms 里的条目 + { name, sun, shade, …place() 的 extra }
    const c = tone(k, at, C);                    // 物件正面不在阳光里时，材料色自动压暗
    // … 正面画在 (at.cx, at.baseY, at.h) 这个框里；子部件命名 `${at.name}-xxx`
    return { x, y, w, h, right, bottom, cx, /* 给标注用的锚点 */ };
  },
};
```

- **正视图、真实比例**（宽高比、圆角、屏幕位置按真实产品）。不画任何标志和商标。
- **光从左上来**（窗在左墙）：亮面、侧面、背光面三档。左边的圆角边更亮，右边的更暗；凹进去的地方（屏幕凹槽）上、左内壁暗，右、下内壁亮。
- **需要看见深度的物件**（打开的壳、立方体）用 `worldBox(at, real)` + `project(x, h, z)` 画真透视：房间的消失点在 (6.67, 3.6)，相机眼高 3.6——比 1 ft 的立方体顶面还低，所以**看不到立方体的顶面**，只看到正面和朝向消失点那一侧的侧面（design.md 写的“等轴测”在这间房间里改为真透视）。
- 物件自己身上的阴影（壳内壁、凹槽）用 `at.sun` 里的 `dir` 计算，见 `objects/mac-case.js` 第 5 段。
- 示意的东西（签名、屏幕上的图标）在页面上写明“示意”。
- **不是一个盒子的物件怎样投影**：`room.py` 只认立在地上的长方体。斜靠在墙上的板子用 `lean`（见第 3 节）。其他轮廓（S08 的 Apple II：低的前沿、斜的键盘、高的机盖）在 `rooms/<ID>.json` 里手写一串“只投影、不画”的阶梯盒子：物件本身 `shadow: false`，再登记几个同 `use`、不同 `id` 的条目（`step-1`…），用 `w_mm / h_mm / d_mm` 和 `baseY` 拼出轮廓——同样宽，前低后高，每一级向墙退一点；页面不 `place` 这些条目，它们只在 `room.py` 里挡光。级数 8–12 足够，影子的台阶会被半影抹平。
- `place(k, id, extra)` 画一个已登记的物件；`extra` 传给 `draw`，常用：`build`（整件物件第几次单击出现）。

## 6. 一页的写法

```js
// S13 — 主体 + 尺寸线：……（构图动作；主角；视觉中心）
const { sun, place, lifeline, linksBefore, marks, leader, dim } = require('../parts');

module.exports = {
  id: 'S13', title: 'NeXT', rhythm: 'dense', transition: 'morph',
  notes: `……写满：口播稿（按单击分段，标（单击 1）…）、口头补充、来源编号……`,
  build(k) {
    sun(k);                                                    // 1 阳光（最底层，在房间之上）
    marks(k, { part: '三　荒野', date: '1985–1993　NeXT', big: true });  // 2 部标记 + 本页年份
    lifeline(k, { current: '1985', links: linksBefore('S13') });        // 3 地板上的生命线
    const cube = place(k, 'next-cube');                        // 4 房间里唯一的东西
    k.light({ cx: cube.cx, cy: cube.y + cube.h / 2, r: 2.6, strength: 0.5 });  // 5 物件周围微弱的暖色反光（可选）
    k.text('一个完美的立方体。', { style: 'headline', x: k.M.x, y: 0.95, w: 6 });  // 6 写在墙上的字
    // … 标注、尺寸线、他的话
  },
};
```

版式（从样张定下来的，照做）：

| 元素 | 写法 |
|---|---|
| 部标记 / 年份 | `marks()`：左上 label（每部第一页 `big: true`），右上 label，y 0.4 |
| 标题 | `headline`（Songti SC 40pt，ink），左上 `(k.M.x, 0.95)`；一句话，句号结尾；一行放得下就一行 |
| 他的话 | `voice`（20–26pt，graphite）+ 下方 `caption` 出处（“斯坦福大学毕业典礼，2005”） |
| 西文原文 | `voiceEn`（Hoefler Text Italic 17pt） |
| 大数字 | `number`（Hoefler Text 200pt）。Hoefler 的数字是旧式的（3、9 下沉，0 与小写等高），保留；旁边标题的最后一行与数字共用基线（见 S12） |
| 物件标签 | `caption`，放在物件下方的地板上，`y = bottom + 0.1` |
| 引线 / 尺寸线 | `leader()`（seam 0.5pt + 末端小点），`dim()`（工程图式，只标真实规格） |
| 墙上图解 | `stroke()` / `strokes()`（平滑曲线），graphite 0.75–1pt；节点就是文字；让光斑落在重点上 |
| 生命线 | S02–S22 每页都有：`lifeline(k, { current, links: linksBefore('Sxx'), fresh, freshBuild, freshLabel, labels, linkLabels })`；S12 用 `until: '1985'` |
| 联系线 | 本页新连上的用 `fresh`（2.25pt，最后一次单击出现）；之前的自动 1pt；标签用 link 蓝。地板上的弧高按 `parts.LINK_H` 逐条给定（同一端点的几条弧至少差 0.1 in，最高 0.72 in）；墙上主图尺度（S23）用 `LINK_H_WALL`（跨度 × 0.35、上限 2.4 in，共端点的拉开） |
| 页内出现 | 先物件（或图解结构）→ 再那一句话 → 最后联系线；1–3 次单击；一次单击里的依次出现用 `[step, delay]`，总长 ≤ 1 s |
| 备注 | 每页写满；按单击分段；示意的内容在备注里说明；末尾写来源编号 |

一页最多 4 个字号（屏幕里的例子不计）。颜色只用 theme 里的；“彩色”只有物件材料色和联系蓝。

### Morph 名（跨页同名才会被配对）

## 7. 并行补页

几个会话可以同时补页，规则只有几条：

1. **只动自己的文件**：`slides/<ID>-*.js`、`rooms/<ID>.json`、`assets/sun/<ID>.*`，以及自己新建的 `objects/<name>.js`（新建前 `ls objects/`，别人可能已经做了；物件按东西命名，一物一文件）。
2. **共享文件不改**：`theme.js`、`parts.js`、`room.json`、`room.py`、`assets/room.jpg`、`deck.js`、别人的物件。缺一个共享部件时，先写在自己的页面文件里，报告里提出“建议移进 parts.js”。缺颜色时，物件材料色写进物件文件；文字颜色只用 theme 的。
3. **只算自己的阳光**：`python3 room.py S13 S14`。不带页号会重算所有页；`--room` 会重画整间房（两者都只由主会话做）。
4. **用自己的 lane 构建**：`./lane.sh <你的名字> S13,S14,S15`。每个 lane 有自己的 `out/`、`renders/` 和 LibreOffice 配置（`TMPDIR`），互不干扰；渲染图在 `_lanes/<名字>/renders/`。不要同时对整个 deck 跑 `make.js`。Morph 序列（S07→S08、S13→S16、S19→S20、S22→S23）放在同一个会话里做。
5. **不提交**：项目 git 由主会话统一提交（并发提交会撞上 git 的锁）。报告里列出你新建和修改的文件。
6. **报告里如实写**：哪些是已渲染检查、哪些是启发式检查、哪些未验证（Morph 和页内动效只能在 PowerPoint 里放映检查）。

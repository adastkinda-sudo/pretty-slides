# Pretty Slides

面向 AI Agent 的 PowerPoint 演示制作协作规范，适用于课程知识交流、学术分享与技术讲解。

Pretty Slides 从主题和资料出发，通过内容开发、视觉分镜、设计规划、原型验证和增量制作，组织用户与 Agent 完成原生可编辑的 PowerPoint 演示文件。整个流程服务于演讲者主导的演示：画面帮助观众理解知识，口头讲解与演讲者备注承载展开说明。

## 核心原则

- **内容驱动**：知识结构决定视觉表达，准确性、必要条件和真实数据优先。
- **视觉优先**：图像、图解、模型与图表承担知识表达，文字用于提示、标注和强调；公式、定义和代码以准确可读为先。
- **动态增强**：动画服务于顺序、因果、状态变化和空间连续性，按内容需要设计。
- **按方案制作**：设计选择在分镜、规划和原型阶段确定，正式制作严格落实已确认的逐页方案；仍无法确定或实现的部分交由用户确认。
- **可持续修改**：保留制作来源、支撑数据、关键素材和用户手工调整，成品反馈在同一项目中继续处理。

## 仓库文件

| 文件 | 作用 |
|---|---|
| [re_agent.md](re_agent.md) | Agent 执行入口，指向工作流、设计规范和项目状态 |
| [workflow_guidelines.md](workflow_guidelines.md) | 协作阶段、确认节点、制作要求、反馈处理、恢复与验收规则 |
| [aesthetic_guidelines.md](aesthetic_guidelines.md) | 内容驱动、视觉优先、动态增强，以及构图、配色、字体和整套演示节奏 |

执行入口目前使用 `re_agent.md` 文件名。启动任务时应显式要求 Agent 读取它和两份规范；采用 `AGENTS.md` 名称时，按实际文件路径启动。

协作步骤与验收以工作流规范为准，审美原则以美学规范为准。本次演示的内容、分镜和具体设计记录在项目文件中，相关资料与技术说明按当前阶段需要加载。

## 七阶段工作流

| 阶段 | 目标 | 主要成果 |
|---|---|---|
| 01 内容开发 | 确定讲解目标，核实知识，组织叙事 | `content.md` |
| 02 视觉分镜 | 将知识转化为场景、对象关系和状态序列 | `storyboard.md` |
| 03 定向素材准备 | 按场景取得、生成与加工素材，记录状态和来源 | `assets/`、`asset_manifest.md` |
| 04 整体设计规划 | 确定整套视觉系统、逐页构图和动态实现 | `design_plan.md` |
| 05 多类型原型 | 用真实内容验证外观、可编辑性和动态能力 | 原型演示文件及真实预览 |
| 06 增量制作 | 按已确认方案分批制作、渲染和修复 | 累计草稿、预览与制作工程 |
| 07 质量检查与交付 | 核查完整成品及其使用体验 | 正式演示、源工程与质量报告 |

标准模式保留完整确认节点；轻量模式合并部分确认，仍保留必要的制作、原型和真实验收。阶段依赖与授权范围见[工作流规范](workflow_guidelines.md)。

## 开始一个演示项目

1. 为本次演示准备独立、可写的项目目录，放入执行入口和两份规范。
2. 将原始参考资料放在 `sources/`，加工结果另存，保留原始文件。
3. 提供主题、受众、讲解时长、必要内容、播放环境及截止时间或资源限制。
4. 让 Agent 检查已有材料与确认记录，完成技术预检，并提交执行方案供用户确认。
5. 按确认后的工作模式推进，规划文档和目录随实际阶段创建。

可使用以下启动指令，并填写具体信息：

```text
请显式读取 re_agent.md、workflow_guidelines.md 和 aesthetic_guidelines.md，
存在 project_status.md 时先读取当前阶段与确认记录，按规范与我协作。
本次用于演讲者主导的演示。
先检查已有材料，补齐必要信息，完成技术预检，提出执行方案供我确认。
制作严格落实已确认的逐页设计方案；仍无法确定或实现的部分先向我确认。

本次主题：
现有资料：
受众与讲解时长：
必须保留的内容：
播放环境：
截止时间或资源限制：
```

完整启动提示词与项目目录约定见[工作流规范](workflow_guidelines.md)。

## 质量与交付

默认交付正式 `.pptx` 演示、来自最终文件的逐页预览与缩略图总览、制作工程与支撑资料，以及内容、分镜、设计方案、素材清单和质量报告。

验收关注以下内容：

- 内容、公式、术语、对象关系与来源准确，符合已确认的讲解目标。
- 正式页面落实已确认设计，文字、图形、表格、图表等满足约定的编辑要求。
- 素材文件存在并通过验收，来源、加工版本、缺口与替代方案可追溯。
- 数据与计算、图表的视觉编码分别核对，数值与图形比例一致。
- 最终文件逐页渲染；动态播放与讲解体验分别检查，未验证部分如实记录。
- 成品、制作输入、预览与验收证据绑定到对应版本，修改后重新检查受影响部分。

完成后的用户反馈继续纳入原项目，更新受影响的内容、方案、成品和验证证据，并保留已确认版本与必要恢复点。

## 制作工具

当前仓库以协作工作流和美学规范为核心。每个演示项目根据环境和目标选择制作、素材处理与渲染工具，并在启动预检及真实原型中验证所需能力。

工具与技术说明按使用需要加载。实际能力、兼容性、重建范围和未验证边界记录在对应演示项目中，交付时以真实文件与验证证据为依据。
